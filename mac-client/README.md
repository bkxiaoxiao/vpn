# Relay 企业连接 · macOS 测试客户端

独立 SwiftUI/AppKit 客户端，复用 `enterprise-server` 的资源与配置服务，内置 sing-box 1.13.21。原 Karing 工程有缺失源码，因此本包不是从当前 Karing 工程直接编译产生的。

## 安装

产物：`dist/Relay-Enterprise-0.1.2-macOS-arm64.dmg`，约 21 MB；Apple Silicon，macOS 13 或更新系统。将应用拖入 Applications 后打开。当前为本机 ad-hoc 签名，未经过 Developer ID 签名和 Apple 公证；其他机器上的 Gatekeeper 接受情况未验证。

客户端保持严格飞书准入。当前服务已部署并配置飞书，默认连接 `https://vpn-243359801139.asia-east1.run.app`。登录可用范围由飞书后台管理；能登录不等于已获授权或已分配节点。服务端未发布配置或员工没有资源池时仍不能连接。

## 认证门槛

- 没有匿名模式、测试账号、原始订阅导入或自定义节点入口。
- 未登录时，同步与连接按钮禁用；凭证未配置时登录返回明确失败并继续锁定。
- 0.1.1 使用默认浏览器和固定回调 scheme，修复 ASWebAuthenticationSession 返回启动成功却不出现窗口时一直等待的问题；授权码仍只交给服务端。
- 登录中可重新打开浏览器、取消并重试；等待超过 5 分钟自动结束。只接受当前待处理事务的完整回调，过期、重复、错误事务或额外重复参数不会完成登录。
- 桌面发起登录时生成随机 verifier，以 SHA-256 challenge 绑定事务。企业 HTTPS 回调验证飞书企业和员工后，只向应用返回短期一次性票据；不在 URL 传递访问令牌或节点密钥。
- 票据必须由发起登录的客户端携带 verifier 兑换；错误绑定、过期、重复兑换都会失败。
- 设备会话由服务端真实飞书认证后签发，客户端会话最多 8 小时。设备安装标识仅用于同一员工重新登录时复用设备记录，不是认证凭证。
- 管理后台密码、本机开发管理员身份、后台手动创建设备令牌，都不能获取或使用客户端配置。
- 令牌只保存在内存。应用重开要求重新进行飞书登录；企业服务设置和随机安装标识可以保存，但不保存登录凭证或可导入的离线节点配置。
- 每次连接前重新获取授权与配置；运行期间每 30 秒校验，约每 5 分钟同步。注销、过期、撤权、控制服务无法访问或核心退出会清理登录状态并停止代理。
- 连接中可选择其他已授权线路；切换前重新校验服务端授权，核心 selector 切换后确认实际选择，本地端口保持不变。已有连接会被中断并在新线路重建；不重新设置系统代理或请求系统代理权限。切换未确认时读取实际线路，仍无法确认则断开。
- 首次连接检测所有已授权线路的延迟，之后连接期间每小时更新，最多 4 条并发。经各线路发送 HTTPS HEAD 到公开检测地址，结果为访问该地址的耗时，不是带宽或纯 ICMP ping。失败显示“超时/不可达”，未检测显示“未检测”。检测不会修改选中线路。
- 延迟结果只在当前登录内存中保留。断开时取消检测；授权线路或发布版本变化时清空缓存；退出登录时清理结果。休眠错过刷新时，在恢复后下一次授权维护周期补测。
- 活跃运行所需的节点配置放在用户 Application Support 的专属 0700 目录、0600 文件中，停止/退出时删除。系统仍可能留下文件系统恢复痕迹，不能据此保证机器所有者无法提取凭证。

## 代理与恢复

本版提供 mixed HTTP/SOCKS 本地代理，并可接管当前活动网络的 HTTP/HTTPS/SOCKS 系统代理。它不是 Network Extension/TUN VPN；不遵循系统代理的应用不会自动被代理，首版不承诺 UDP/QUIC 全设备覆盖。

接管前保存原代理状态，断开/退出时恢复。已有认证代理、PAC 或自动代理发现时拒绝自动接管，用户可取消该开关，使用本地端口对单独应用测试。正常接管需要 macOS 管理员授权，测试中没有修改真实系统代理设置。

若应用异常终止，独立看护脚本会检查父进程并停止核心。系统代理恢复需要系统授权，因此若崩溃留下代理设置，应重新打开应用并点击“恢复网络代理”。网络服务切换后应先断开再连接，避免同时由多个代理软件接管。

## 构建

需要 Xcode/Command Line Tools 和 arm64 sing-box 可执行文件；默认使用 `/opt/homebrew/bin/sing-box`。可通过 `SING_BOX_PATH` 指定同架构的核心。

```sh
sh mac-client/scripts/build.sh
sh mac-client/scripts/test.sh
```

脚本输出 `.app`、DMG 与 `SHA256SUMS.txt`；调用 swiftc 编译原生源码，生成图标，签名核心和应用并检查包结构。系统图标/磁盘映像工具在严格沙箱内可能无法访问 macOS 服务。

源码：

- `Sources/EnterpriseAPI.swift`：服务 URL 校验、HTTPS/本机 HTTP 请求、策略格式与认证标志校验。
- `Sources/AppModel.swift`：登录状态、票据绑定、同步、连接、周期验证、注销。
- `Sources/BrowserLogin.swift`：默认浏览器打开、待处理回调、取消和超时。
- `Sources/ProxyEngine.swift`：受控核心配置、回环端口、核心校验与生命周期。
- `Sources/CoreController.swift`：带随机密钥的回环控制接口、在线 selector 切换和逐线路 HTTPS 延迟检测。
- `Sources/RouteLatency.swift`：延迟状态和一小时缓存有效期。
- `Sources/SystemProxy.swift`：网络代理快照、系统授权与恢复。
- `Sources/RelayApp.swift`：原生 UI。
- `Resources/core-watchdog.sh`：父进程消失时终止核心。

## 后续配置

1. 创建飞书企业自建应用，配置应用可用范围及必要身份权限。
2. 在服务端配置 App ID、Secret、tenant_key、正式 HTTPS 基地址；不要把 Secret 填进客户端或聊天。
3. 在飞书后台注册 `https://企业服务/auth/feishu/callback`。
4. 在后台添加该飞书应用下的员工 open_id，分配资源池并发布版本。
5. 将客户端服务地址改为 HTTPS 基地址，重新通过飞书登录。

如果需要员工用量，部署已有计量网关并为桌面设备分配网关后使用 gateway 分发模式。直连外购节点不提供可信员工计量，也不能靠本机 UI 锁定保证外购共享密码的网络侧失效。
